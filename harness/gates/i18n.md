# Gate: Internationalisation (i18n)

**Enabled: no** — this project contains no user-visible strings in source code.
All output is markdown skill instructions and shell scripts; i18n does not apply.

All user-visible strings introduced by a task must be wrapped in the project's
localisation helper (e.g. `t()`, `i18n.t()`, `useTranslation`). Prevents hardcoded
display text from accumulating in the codebase and becoming costly to localise later.

**Enabled (general):** opt-in — add this gate for projects that support or plan to support
multiple locales. Not applicable to CLI tools or APIs that do not render user-facing text.

**Runs: both** — can be run locally as a lint-style scan before `cc:done`; also enforced as a CI step after lint on every push.

---

## What It Checks

After the task's code changes, scan all modified files for raw string literals in
user-visible positions. A string is considered user-visible when it appears in:

- JSX/TSX text content: `<Text>Hello world</Text>`
- Component props that render to the UI: `placeholder="Enter name"`, `label="Submit"`
- Notification or alert content: `Alert.alert("Error", "Something went wrong")`
- Toast or snackbar messages
- Button labels, modal titles, form field labels

The gate fails when any such string is a hardcoded literal rather than a localisation
helper call. Example patterns that fail:

```tsx
// FAIL — hardcoded user-visible string
<Button title="Save changes" />
showToast("Saved successfully")

// PASS — wrapped in localisation helper
<Button title={t("actions.save")} />
showToast(t("feedback.saved"))
```

**Exempt — strings that do NOT need localisation:**
- Internal error codes and log messages (developer-facing, not user-facing)
- Translation key identifiers themselves: `t("some.key")`
- Test fixture strings in test files
- URLs, identifiers, and non-display constants
- Comments and documentation

---

## Pass

All user-visible string literals introduced by the task are wrapped in the project's
localisation helper, or the task introduces no user-visible strings.

## Fail

The i18n gate fails when a task introduces a hardcoded user-visible string outside a
localisation call:

```
i18n gate: hardcoded user-visible string(s) found.
  src/components/SaveButton.tsx:12 — "Save changes"
  src/screens/Home.tsx:34 — "Welcome back"
Action: wrap these strings in the localisation helper before marking cc:done.
```

---

## Skipping

Add `[no-i18n: <reason>]` to the task row when localisation is intentionally deferred.
Valid reasons: `prototype only`, `locale support not planned`, `string is a proper noun`.
